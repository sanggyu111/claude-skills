# 문서 시각 정리

사용자가 보낸 문서를 읽고, 그 구조를 눈으로 따라갈 수 있는 HTML 페이지로 만든다. 줄글 요약만 있으면 원문을 읽는 것과 다르지 않다. 그래서 이 스킬이 만드는 가치는 **그림**이다. 글은 그림을 읽는 법을 돕는 짧은 안내로만 쓴다.

## 1단계: 문서를 끝까지 읽기

| 입력 | 읽는 방법 |
|---|---|
| 웹 페이지 URL | WebFetch. 결과가 잘렸으면 `offset`으로 이어서 끝까지 읽는다. 수치, 고유명사, 조건은 "원문 표현 그대로" 달라고 요청한다. |
| PDF | Read의 `pages`로 20쪽씩 나눠 끝까지 읽는다. |
| Word(.docx) | `pandoc file.docx -t markdown`으로 텍스트를 뽑는다. pandoc이 없으면 docx 스킬을 쓴다. |
| Markdown, 텍스트 파일 | Read로 읽는다. |
| 붙여 넣은 텍스트 | 그대로 쓴다. |

- 문서를 다 읽기 전에 구조를 정하지 않는다.
- 일부를 읽지 못했으면(로그인 필요, 잘림, 이미지 속 글자 등) 페이지 끝 `callout`과 답변에 그 사실을 밝힌다.

## 2단계: 뼈대 뽑기

쓰기 전에 아래를 먼저 정한다.

1. **문서가 답하는 질문 하나.** 이것이 `tldr`이 된다.
2. **섹션 3~7개.** 원문 목차를 그대로 옮기지 말고, 독자가 알고 싶은 질문 단위로 다시 묶는다.
3. **섹션마다 내용 유형.** 아래 표로 그림을 고른다.

| 내용 유형 | 원문의 신호 | 블록 |
|---|---|---|
| 절차, 과정, 데이터 흐름, 인과 | 단계, 순서, "~하면 ~된다", 입력과 출력 | `flow` |
| 갈림길이 있는 과정 | "~이면", "그렇지 않으면", 조건 | `flow`의 `decision` 노드 |
| 시간 순서, 버전, 단계적 출시 | 날짜, "이후", "먼저", 로드맵 | `timeline` |
| 여러 대상 비교 | 플랜, 옵션, 버전, 장단점 | `compare` |
| 핵심 수치 | 한도, 비율, 가격, 기간 | `stats` |
| 나란한 개념이나 종류 | 기능 목록, 권한 종류 | `cards` |
| 제한, 예외, 주의 | "단", "불가", "주의", "~만" | `callout` (warn) |
| 위 어디에도 맞지 않는 짧은 설명 | | `text` |

- 문서에 흐름이 있으면 `flow`를 **하나 이상** 만든다. 흐름도는 `steps`로 처음부터 끝까지 따라가게 하고, 각 단계에서 무엇을 눈여겨볼지 짚는다. 이 스킬의 핵심이다.
- 흐름이 없는 문서(예: 용어 목록)에 흐름도를 억지로 만들지 않는다.
- 모든 섹션에 그림 블록이 최소 하나 있어야 한다. `text`는 3문장 이내로 쓴다.

## 3단계: 정확하게 옮기기

- 수치, 이름, 조건, 날짜는 원문 표기 그대로 쓴다. 반올림하거나 바꿔 말하지 않는다.
- 원문 문장을 흐름도나 표로 재구성했으면 그 블록에 `"derived": true`를 붙인다. 페이지에 "원문을 바탕으로 정리"라고 표시된다.
- 원문에 없는 내용은 넣지 않는다. 배경 설명이 꼭 필요하면 `callout`의 `info` 톤에 `"title": "덧붙임"`으로 따로 표시한다.
- `source`에 원문 제목, URL(있을 때), 정리한 날짜를 넣는다.

## 4단계: HTML 만들기

1. `assets/template.html`을 저장할 위치로 복사한다.
   - 사용자가 위치를 정했으면 그곳에 둔다.
   - 정하지 않았으면 scratchpad 디렉터리가 있을 때는 거기에, 없으면 현재 작업 디렉터리에 `<주제-영문-slug>.html`로 저장한다.
2. 복사본에서 두 곳만 바꾼다.
   - `<title>`: 데이터의 `title`과 같은 값
   - `<script id="doc-data" type="application/json">` 안의 JSON 전체: `references/blocks.md` 형식으로 새로 쓴다
3. 렌더링 코드와 CSS는 고치지 않는다. 템플릿에 없는 그림이 꼭 필요할 때만 새 블록 렌더러를 추가하고, 답변에서 그렇게 했다고 밝힌다.
4. JSON 문자열 안의 `</`는 `<\/`로 쓴다.
5. 검사한다: `python3 <이 스킬 경로>/scripts/validate.py <만든 html>`. 문제가 나오면 고치고 다시 검사한다.

## 5단계: 보여주기

- **Artifact 도구가 있으면:** 그 도구의 규칙에 따라 게시한다(비공개로 게시됨). 게시 전에 그 도구가 요구하는 디자인 지침을 불러온다. 템플릿은 이미 그 계약(테마 토큰, 다크 모드, 모바일 여백)을 지키고 있다.
- **Artifact 도구가 없으면:** 파일 경로를 알려주고 `open <경로>`로 열 수 있다고 안내한다.

## 답변 형식

채팅에는 결과물 내용을 다시 쓰지 않는다. 아래만 짧게 쓴다.
- 링크나 파일 경로
- 섹션별로 어떤 그림을 썼는지 한 줄씩 (예: "2. 플랜 비교 → 비교표, Team 열 강조")
- 재구성한 부분(`derived`)과 원문에서 읽지 못한 부분
- 다음에 할 수 있는 것 한 줄 (예: "특정 섹션을 더 자세한 흐름도로 쪼갤 수 있어요")

## 하지 않는 것

- 줄글 요약만 있는 페이지를 만들지 않는다.
- 원문에 없는 수치나 사실을 지어내지 않는다. 확인하지 못한 링크 주소를 만들지 않는다.
- 사용자가 요청하지 않았는데 문서 전체를 번역하거나 다시 쓰지 않는다. 정리는 원문 언어와 상관없이 한국어로 하되, 고유명사와 UI 용어는 원문 표기를 괄호로 함께 쓴다.
- 회사 내부 문서처럼 민감해 보이는 문서는 공개 링크로 게시하기 전에 사용자에게 확인한다.
