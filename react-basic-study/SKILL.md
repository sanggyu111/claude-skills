# React 배열 기초

React 입문자가 배열을 추가했을 때, 화면이 바뀌지 않는 문제를 점검하고 입문자의 눈높이에 맞춰 설명한다.

## When to Use
배열에 추가하고 화면이 바뀌지 않는 오류 상황에 대해서 이유를 물을 때
push를 했는데 화면에 목록이 추가되지 않을 때

Next.js, 스타일, 성능에 관한 요청은 아래 "하지 않는 것"에 따른다.

## 점검 순서

### 1. 파일 읽기
사용자가 지정한 파일 읽기. 지정한 파일이 없으면 src/ 에서 .jsx 파일을 읽는다.

### 2. 규칙 점검
규칙의 "왜"를 결과 설명에 그대로 활용한다.

**state를 직접 수정하지 않는가** (push, 직접 대입 금지)
   - 왜: React는 내용이 아니라 배열/객체가 새것인지(같은 상자인지)를 비교한다. push로 같은 배열을 넘기면 "변화 없음"으로 보고 화면을 다시 그리지 않는다.
   -  `todos.push(x); setTodos(todos);` → `setTodos([...todos, x]);`

### 3. 결과 보여주기
'''
   통과: 1(key), 3(대문자)
   위반: `src/App.jsx:16` — 규칙 (state 직접 수정)
   문제: todos.push 후 같은 배열을 setTodos에 넘김
   왜: React는 같은 배열이면 변화가 없다고 보고 다시 그리지 않음
   고친 코드: setTodos([...todos, newTodo]);
